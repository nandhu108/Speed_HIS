## Stack

- **Backend:** .NET 10 Web API, EF Core 10 (Code First) + Npgsql, PostgreSQL 16, Serilog, FluentValidation, Hangfire, QuestPDF. Clean Architecture: `Prixo.Domain` → `Prixo.Application` → `Prixo.Infrastructure` → `Prixo.Api` (references point inward only; Domain has zero dependencies; Application defines interfaces that Infrastructure implements).
- **Frontend:** React 18 + Vite + TypeScript (`strict`) + Tailwind CSS (chosen over Bootstrap — do not add Bootstrap), React Router 6, TanStack Query 5 (no Redux), Axios, React Hook Form + Zod.
- Planned layout: `backend/` (solution), `frontend/`, `docker/`, `docs/modules/` (per-module specs written as each phase begins). Feature folders mirror each other across Domain entities, Application features, API controllers, and frontend `src/features/`.

## Commands

```bash
# Full dev stack (db + api + web; add --profile tools for pgadmin on :5050)
docker compose -f docker/docker-compose.yml up -d
docker compose -f docker/docker-compose.yml up -d db   # just PostgreSQL for local dev

# Backend (from backend/ — solution file is Prixo.slnx, the new XML format)
dotnet build Prixo.slnx
dotnet test Prixo.slnx                               # all tests
dotnet test --filter "FullyQualifiedName~BillMath"   # single test
dotnet ef migrations add <Module>_<Change> --project src/Prixo.Infrastructure --startup-project src/Prixo.Api --output-dir Persistence/Migrations
dotnet ef database update --project src/Prixo.Infrastructure --startup-project src/Prixo.Api
dotnet run --project src/Prixo.Api --urls http://localhost:5000   # Scalar API docs at /scalar/v1

# Frontend (from frontend/)
npm run dev          # Vite dev server on :3000, proxies /api to :5000
npm run build        # tsc -b && vite build
npm run lint         # oxlint
```

dotnet-ef is a local tool (`backend/dotnet-tools.json`); run `dotnet tool restore` after a fresh clone. Dev DB credentials live in `appsettings.Development.json` and match `docker/docker-compose.yml` defaults.

Never use `EnsureCreated` or auto-migrate on app start; migrations are explicit and named `YYYYMMDD_<Module>_<Change>`.

## Non-negotiable conventions (plan §5–§10)

- **Every business table/entity** carries `Id, CreatedAt, CreatedBy, UpdatedAt, UpdatedBy, IsActive, IsDeleted` (via `BaseEntity`; branch-scoped entities extend `BranchEntity` with `BranchId`). Soft delete only — `DELETE` endpoints set `IsDeleted`; global EF query filters enforce `!IsDeleted` and branch scoping. Unique indexes are partial: `WHERE is_deleted = false`.
- **Multi-branch:** single DB, `branch_id` discriminator. Patients/UHID, users, roles, ICD, drug and service catalogs are global; all transactional data and operational masters (beds, tariffs) are branch-scoped. Cross-branch reads require `IgnoreQueryFilters()` + `REPORT.CROSSBRANCH.VIEW` permission.
- **API shape:** every endpoint returns `ApiResponse<T>` (`success, message, data, errors, traceId`); lists return `PagedResult<T>`. Workflow state changes are explicit action endpoints (`POST /bills/{id}/cancel`), never generic status PATCH. Base path `/api/v1/`.
- **Auth/RBAC:** JWT (15 min) + rotating hashed refresh tokens. Permissions use `MODULE.RESOURCE.ACTION` codes seeded from a code registry; every endpoint gets `[HasPermission(...)]` — no anonymous endpoints except login/refresh/portal-auth/health. Permissions are NOT embedded in the JWT. Frontend permission checks are cosmetic; the API is the gate.
- **Transactions are mandatory** (via `IUnitOfWork.ExecuteInTransactionAsync`) for: billing, payments/refunds, pharmacy sale/issue, GRN, stock transfer/adjustment, admission, discharge, day close. Stock movements always write an append-only `stock_ledger` row.
- **Audit:** EF `SaveChangesInterceptor` stamps audit columns and writes row-diff audit logs (changed columns only, `jsonb`) in the same transaction as the change; business events (login/logout, cancellations, approvals, merges) go through `IActivityLogger`. Audit tables are append-only.
- **DTOs in/out only** — entities never cross the API boundary. FluentValidation validator per request DTO. Controllers are thin: parse → service → `ApiResponse`.
- **No hardcoded hospital data** — every dropdown/reference value is a master table; seed data is idempotent code keyed by stable codes.
- **Placeholders get real schema:** held-module features marked "(placeholder)" in the plan get DB columns/tables and disabled UI now (e.g., ABHA fields, `notification_queue` outbox, PACS accession numbers) so later activation needs no re-architecture.
- **Database naming:** snake_case, PostgreSQL schema per domain (`admin`, `master`, `patient`, `billing`, `lab`, ...). Money `numeric(18,2)`, quantities `numeric(18,3)`, time `timestamptz`. FKs always, `ON DELETE RESTRICT`.
- **Frontend:** feature folders are self-contained (`pages/`, `components/`, `api.ts`, `types.ts`); cross-feature imports only via shared `components/` and `lib/`. Sidebar menu is data-driven from `/api/menus/my`. Server state only through TanStack Query hooks with namespaced keys (`['opd','queue',{...}]`).
